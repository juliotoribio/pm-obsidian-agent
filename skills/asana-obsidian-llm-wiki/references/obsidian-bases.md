# Obsidian Bases (.base) — native views over the wiki frontmatter

Bases turn the wiki's YAML frontmatter into **live tables, cards and lists**
inside Obsidian — sortable, filterable, with computed columns. No scripts, no
build step, no database. This is the natural third layer on top of the
Asana→Obsidian sync: the sync writes correct frontmatter, and Bases *reads* it.

**It is the answer to "how do I see the portfolio without asking the agent?"**

## Requirements

- **Obsidian ≥ 1.9** for Bases. Verify before promising anything:

```bash
defaults read /Applications/Obsidian.app/Contents/Info.plist CFBundleShortVersionString
```

⚠️ **Check this FIRST.** Bases is a core plugin; on an older build the file
opens as raw YAML and the user sees nothing. Do not generate a `.base` and
report success without confirming the version — the failure mode is silent and
looks like your file is simply broken.

- Core plugin **Bases** enabled (Settings → Core plugins).
- No community plugins, no embeddings, no vector DB. Pure YAML + Markdown.

## Where it goes

Drop the `.base` file anywhere in the vault. It reads notes by **filter**, not
by location, so `02 Projects/Proyectos.base` works fine and keeps it beside the
notes it summarizes.

Nothing is modified — a `.base` is a *view*. It never writes to your notes and
never touches the `HERMES:START/END` blocks.

## Minimal working file

```yaml
filters:
  and:
    - 'type == "project"'
    - 'source == "asana"'

formulas:
  dias_para_vencer: 'if(due_date, (date(due_date) - today()).days, "")'
  antiguedad_sync: 'if(last_synced_at, (now() - date(last_synced_at)).hours.round(0), "")'

properties:
  file.name:
    displayName: Proyecto
  formula.dias_para_vencer:
    displayName: Días

views:
  - type: table
    name: "Todos"
    order:
      - file.name
      - status
      - owner
      - due_date
      - formula.dias_para_vencer
    groupBy:
      property: status
      direction: ASC
```

View types: `table`, `cards`, `list`, `map` (map needs lat/lng + Maps plugin).

## Validate BEFORE handing it over

The user opens this in a GUI; a YAML error renders as a blank pane with no
useful message. Validate programmatically first:

```python
import yaml
d = yaml.safe_load(open(path))

defined = set(d.get("formulas", {}))
used = {str(o).replace("formula.", "")
        for v in d.get("views", []) for o in v.get("order", [])
        if str(o).startswith("formula.")}
assert used <= defined, f"undefined formulas: {used - defined}"

real = {  # actual frontmatter keys in the notes this filter selects
    'asana_gid','asana_url','due_date','last_synced_at','owner',
    'source','source_hash','start_date','status','type','workspace'}
props = {str(o) for v in d.get("views", []) for o in v.get("order", [])
         if not str(o).startswith(("file.", "formula."))}
assert props <= real, f"props not in notes: {props - real}"
```

**Four checks, in order:**

| Check | Why it matters |
|---|---|
| `yaml.safe_load` parses | A syntax error = blank pane, no message |
| Every `formula.X` used is defined | Undefined refs fail **silently** |
| Every property exists in the notes' frontmatter | Typo = permanently empty column |
| Quote style is legal | See below |

Enumerate the real frontmatter keys from the notes themselves before writing
the `.base` — don't write filters against fields you assumed exist.

## Quoting rules (the #1 source of breakage)

- A formula containing `"` must be wrapped in **single** quotes:
  `'if(done, "Yes", "No")'` ✅ / `"if(done, "Yes", "No")"` ❌
- Plain strings containing `:`, `{`, `}`, `[`, `]`, `,`, `&`, `*`, `#`, `?`,
  `|`, `-`, `<`, `>`, `=`, `!`, `%`, `@`, `` ` `` must be quoted.

## Formula gotchas

**Date subtraction returns a Duration, not a number.** Access a numeric field
before doing math:

```yaml
"(date(due_date) - today()).days"        # ✅ number
"(date(due_date) - today()).round(0)"    # ❌ Duration has no .round()
"(date(due_date) - today()).days.round(0)"  # ✅
```

**Guard for missing properties** — not every note has every field, and an
unguarded reference on an empty value is the classic crash:

```yaml
'if(due_date, (date(due_date) - today()).days, "")'   # ✅
'(date(due_date) - today()).days'                     # ❌ empty date breaks it
```

Useful functions: `date()`, `now()`, `today()`, `if()`, `duration()`,
`file()`, `link()`. File props: `file.name`, `file.basename`, `file.folder`,
`file.mtime`, `file.tags`, `file.links`, `file.backlinks`.

## Emitting `.base` files from the sync

Treat a `.base` as a **generated artifact** when it should track the wiki
schema. In practice: write it once, commit it, and regenerate only when the
frontmatter contract changes. The user edits views themselves freely — it is a
view layer, so their tweaks are safe to keep.

If a `.base` is regenerated by a script, give it the same treatment as notes:
report before writing, and never silently replace one the user has curated.
